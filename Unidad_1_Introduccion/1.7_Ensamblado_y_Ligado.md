# 1.7 Proceso de ensamblado y ligado

## El Flujo de Trabajo del Bajo Nivel
El código fuente escrito en lenguaje Ensamblador (`.asm`) es texto plano que el procesador no puede ejecutar directamente. Para convertirse en software funcional, debe pasar por un proceso de traducción y empaquetado dividido en dos fases arquitectónicas distintas.

## Fase 1: El Ensamblador (Assembler)
* **Entrada:** Archivo de código fuente (`.asm`).
* **Proceso Técnico:** Traduce los mnemónicos (ej. `MOV`, `ADD`) e identificadores humanos a códigos de operación binarios (*opcodes*) específicos de la arquitectura (ej. x86). Valida la sintaxis del lenguaje.
* **Salida:** **Archivo Objeto** (`.o` o `.obj`).
* **Limitación:** El archivo objeto contiene código máquina real, pero no se puede ejecutar porque contiene **referencias no resueltas** (direcciones de memoria de funciones externas o del sistema operativo que aún no se conocen).

## Fase 2: El Ligador (Linker)
* **Entrada:** Uno o más archivos objeto (`.o`) y posibles bibliotecas del sistema.
* **Proceso Técnico:** Realiza la **Resolución de Referencias**, calculando y asignando las direcciones de memoria definitivas para conectar las llamadas a funciones externas entre los diferentes archivos. 
* **Salida:** **Archivo Ejecutable** (`.exe` en Windows, binario sin extensión o `.elf` en Linux).
* **Función Clave:** Añade la cabecera estructural requerida por el Sistema Operativo (PE o ELF) que define el punto de entrada de la aplicación (*entry point*) y la ubicación de los Segmentos de Código, Datos y Pila para que el programa pueda ser cargado exitosamente en la memoria RAM.
